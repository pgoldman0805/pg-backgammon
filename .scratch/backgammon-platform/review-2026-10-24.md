# pg-backgammon — multi-persona critical review (2026-10-24)

A heuristic review of the shipped app from six independent angles: expert player, complete novice, technician/QA, UI/UX designer, growth-strategy operator, and an independent Codex code review (appended when it completes). Each explored the spec, the code, and the ~150 audit screenshots through its lens. Findings below are deduped, cross-attributed, and prioritized. This is a findings report, not a work order — the "needs work" items are written to be ticket-ready; several of the bug-grade claims should be verified-then-fixed when turned into tickets.

## The core tension

The app is a genuinely **XG-grade engine and analyzer wrapped in a disciplined, polished UI** — reviewers across the board respect the mechanics and the design system. Two structural gaps bound its reach:

1. **It assumes you already play backgammon.** There is no on-ramp for a beginner, and the one feature that teaches (Tutor mode) is off by default and unlabeled. (novice, UI/UX)
2. **The market is small and the GPL license constrains monetization.** It's an excellent personal tool and portfolio piece; as a business it's a ~$75k/yr lifestyle ceiling, and only the *service* layer (not the forkable GPL software) is sellable. (growth)

Underneath those, there are **concrete data-loss and robustness bugs** that matter even for the personal-tool use case, and one **analysis gap that reads as a bug** (perfect opponent cube at every difficulty).

## What's genuinely strong (consolidated)

- **Correct match rules** — dead cube, Crawford firing exactly once, cube-ownership transfer, gammon/backgammon × cube scoring, deterministic replay. Rare in training apps. (expert)
- **One full-strength oracle** for both analysis and Tutor; difficulty never contaminates ground truth. Cube-cost EMG math is theoretically sound. Match-aware equities via XGID/MET. (expert)
- **Disciplined puzzle mining** — screen cheap, confirm at 2-ply, require a clear best (≥0.05 gap), dedupe by content key; the 0.02 grading tolerance is justified by that separation. The "drill your own blunders" loop is a real differentiator no competitor ships well. (expert, growth)
- **Genuinely private and client-only** — the only outbound fetch is the same-origin engine; no analytics, beacons, or third-party hosts. Fair CSPRNG-seeded, bias-free dice. (technician)
- **Sound engine architecture** — all eval off the main thread, payload code-split and precached offline, shell usable before the engine loads, priority gate so the opponent never waits behind an analysis batch. (technician)
- **Resilient storage/parsers** — corrupt rows skipped not thrown, additive schema upgrades, versioned backup, line-numbered .mat/XGID errors validated against rules legality. A real hand-verified golden test against the live WASM. (technician)
- **Rigorous color semantics** — gold = actionable, rust = cost, held honestly across every screen; the board-point triangle is a real identity used three ways; six genuinely distinct board styles; Analyze-review is a standout dense-but-scannable screen. a11y basics present (skip link, focus-visible, keyboard board, role=status, reduced-motion default, text chips not color-only). (UI/UX, technician)

## What needs work

### P0 — Data-loss & correctness (fix first; verify the code claims when ticketing)

1. **No `navigator.storage.persist()` → silent eviction.** iOS purges PWA storage after ~7 days unused; a week away wipes all matches/puzzle progress with no warning. Call `persist()` at startup; surface `estimate()` in Settings. (technician, HIGH)
2. **Restore can destroy history.** `importBackup` does `clear()` then per-row `put()` with no rollback, fired on file-pick with no confirmation — a wrong/old file or mid-restore crash wipes or half-wipes everything. Single transaction / temp-store swap, confirm with match counts, offer merge. (technician, HIGH)
3. **Write failures swallowed.** `QuotaExceededError` and other `put` rejections are caught silently; play continues in memory, nothing persists, reload drops progress. Show a non-blocking "progress isn't saving — export now" banner. (technician, HIGH)
4. **Engine boot has no recovery.** A failed boot is cached as a rejected promise so Retry re-throws forever; no timeout anywhere in the engine path; Retry only renders in `error` state, never `loading`; a worker crash leaves pending promises unsettled. One flaky-wifi wasm fetch can brick the app until a hard reload. Add a timeout → error, have Retry recreate the worker (dispose exists), wire `worker.onerror`. (technician, HIGH)
5. **Opponent plays world-class cube at every difficulty.** `cubeInfo` takes no difficulty parameter — only checker play is noised. "Beginner" shoves checkers randomly but doubles/takes/passes like XG, so you can never punish a loose double or exploit a wrong take — half of cube practice is gone at all five levels. Perturb the cube equities / shift take-and-double points by difficulty. (expert, HIGH — reads as a bug)

### P1 — Reach & credibility (unlock the beginner market; earn the expert's trust)

6. **No "how to play backgammon" anywhere.** No rules, tutorial, or onboarding; a true beginner can't confidently make a first move (direction, the bar, bearing off, "what's the 64 cube?"). A Help/How-to-play nav entry or first-run overlay — the single highest-impact addition for reach. (novice, HIGH)
7. **Tutor mode — the learning feature — is hidden.** Off by default, shown as an unlabeled pill. Default it on for a user's first few matches; relabel "Tutor mode (hints & feedback)" with a one-line hint. (novice, HIGH)
8. **Jargon wall with no in-app glossary.** pips, equity, EMG, Crawford, 2-ply, Dubious appear undefined; the glossary is a dev file users never see. Tooltips / an in-app glossary; explain pips & equity inline on first appearance. (novice, HIGH)
9. **Error-rate isn't labeled as the PR players quote.** The header shows gnubg mEMG (×1000); players calibrate in XG **PR = ×500, exactly half**, and it isn't even called PR — so "30" reads as weak when it's an intermediate PR ~15. Lead with PR (or show both) and map to skill bands. Cheap credibility win. (expert, MED but cheap)
10. **Dark-mode board has no containment.** Frame `#0e120f` ≈ page `#15130f`, so the board edge and off-trays dissolve into the page on every style; borne-off checkers land in invisible trays. Hairline outline or lift frame/felt luminance in dark mode. (UI/UX, HIGH)
11. **Desktop wastes horizontal width on data screens.** The 68ch prose measure squeezes Analyze/Progress/Puzzles-browse into ~500px with huge gutters; the Progress charts (the "am I improving?" payoff) read better on phone. Widen / multi-column for data screens. (UI/UX, HIGH)
12. **One 980KB JS chunk; Play-only users download the 1.3MB curated puzzle set.** No route-level `React.lazy`, no `manualChunks`; Puzzles statically imports `curatedSet.ts`. Route-split and dynamic-import the set. (technician, HIGH — worsens with more puzzles)

### P2 — Depth & polish

13. **2-ply treated as ground truth; no rollouts.** Mis-ranks exactly the close checker/cube decisions near the take point that experts study; a player who knows the rollout answer catches the tool "correcting" toward a 2-ply artifact. Label analysis as "2-ply eval, not rollout"; validate bundled puzzles against truncated rollouts; drop positions where 2-ply/3-ply disagree on the top play. (expert)
14. **Difficulty is symmetric noise over 0-ply gnubg** — random slips, not human error modes (over-hitting, running a back checker, missing gammon danger); combined with perfect cube, the five levels compress into upper-intermediate→world-class. Bias the noise toward real error patterns, widen the low end. (expert)
15. **No spaced repetition** (deferred in spec) — the #1 missing mechanic for a drill app and for retention. (growth, expert-adjacent)
16. **Dialogs aren't modal for assistive tech** — cube/resign/game-over/match-over are plain divs: no `role="dialog"`, `aria-modal`, focus trap/restore, or Escape. (technician, MED)
17. **Cube puzzles are money-only** (`matchLength: 0`) — no score-dependent cube drilling, a core match skill; exposing a proper money-session mode (with Jacoby) is low-hanging. (expert, MED)
18. **No luck/variance metric** — a player can't separate a bad loss from bad dice or sanity-check the PRNG feel. (expert, MED)
19. **Analyzer correctness rests on one real-engine game; the visual audit asserts almost nothing** (only `expect.soft` horizontal overflow). Add hand-verified golden positions across bear-off/backgame/score-dependent cube; add targeted DOM assertions. (technician, MED-HIGH)
20. **Three play controllers (opponent/autoplay/raceAutopilot) duplicate token logic verbatim; `Play.tsx` (1210) and `Analyze.tsx` (1359) are oversized.** Extract a shared controller core; decompose the pages. (technician, MED)
21. **UI consistency**: one concept, three toggle idioms (pill-with-dot vs iOS switch vs text button); Analyze ledger is "button soup" (Open/Export/Delete at equal weight ×13 rows, no sort/filter/search); unlabeled equity columns in Analyze review (the Puzzles reveal labels them); the eval bar reads as a loading bar (12px rail across 1380px with an orphaned number); board-style thumbnails orphan Reykjavik on desktop (5+1 wrap). (UI/UX, MED)
22. **The centered "64" cube** reads as a bug to non-experts in no-doubling/early states — hide the cube in no-doubling matches, or render it so it doesn't assert "64." (UI/UX, MED)
23. **Bosphorus contrast** (confirms ticket 19): gold affordances vanish on warm walnut; dark Bosphorus is muddy. Halo the gold on warm-felt styles; lift the dark felt. (UI/UX, MED)
24. **Novice defaults**: Casual + 7-point match is a marathon a beginner doesn't understand; puzzles open on "Priming" presuming fundamentals never taught. Default Beginner + a quick single game; add a "Basics" theme first. (novice, MED)

### P3 — Lower priority / edge cases

- **No opening reference; openings judged at 2-ply** (disagrees with rollout consensus on several). Bundle a small rollout opening table or suppress error-flagging there. (expert)
- **Resignation acceptance compares base points to *cubeless* equity, ignoring cube scaling** — wrong when the cube >1 (rare path). (expert)
- **IDB open lacks `onblocked`/`onversionchange`** — a future `DB_VERSION` bump with a second tab open hangs every read/write. **.mat** drops comments / can't carry names with `:`; **XGID** match length unbounded. (technician)
- **SW `autoUpdate` reloads unprompted**; `pagehide` flush is fire-and-forget async — a reload within the 250ms debounce can clip the last move. Prompt-defer updates during a live match; mirror in-progress state to localStorage synchronously on hide. (technician)
- **GPL provenance is a mirror, not a from-source build** — SHA-256 pins the bytes but a reproducible build would fully close the "corresponding source" loop. Capacitor shell is hard landscape-locked (a11y for fixed-orientation users). (technician)
- **Page titles near-invisible** (small, ink-muted h1); portrait board quite small. (UI/UX)

## Business / strategy (separate axis — growth operator)

- **TAM is small and already owned** — realistically ~50–250k people worldwide who'd pay to improve; XG owns solo study, Backgammon Galaxy owns modern+social+tournaments. Generous math: 50k × 3% × $49/yr ≈ **$75k/yr ceiling**, with two incumbents already in it.
- **GPL kills selling the software** — anyone can fork the public repo and rehost free; GPLv3 also conflicts with Apple's App Store terms. You *can* sell what GPL doesn't touch: **cloud accounts, cross-device sync, spaced-repetition on your own blunder deck, original content, coaching, community, tournaments** — the service and the network, never the bits. A permissive-engine rebuild is **not** worth it (ADR-0001 got this right).
- **It's configured as the least-monetizable version** — single-player, no accounts, no backend; the money in games lives in the multiplayer/social/competitive layer the spec put out of scope.
- **The one move**: fake-door a "Pro" waitlist inside the already-live free app ($49/yr: account + cross-device sync + SRS on your blunders + weekly packs + streaks/leaderboards — all server-dependent, none forkable), then drive the four BG communities (r/backgammon, Backgammon Galaxy, BGonline/Backgammon Studio, 2–3 coaches/YouTubers) to it. **Measure willingness-to-pay before building any backend.** If the signal's there, build accounts+sync+SRS first; if not, bank it as a portfolio/engineering credential (WASM engine, rules engine, analyzer, PWA).
