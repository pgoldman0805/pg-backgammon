# 23: PWA — the mobile app

**What to build:** The app as an installable, offline-capable PWA (spec story 56, ADR-0003): the phone's delivery path and the mobile-POC dev loop.

- Web app manifest: name "pg-backgammon", short_name, standalone display, theme/background colors matching both app themes sensibly, and real PNG icons (192, 512, plus a maskable variant) generated from the app's mark — commit the generation script, not just the artifacts.
- Service worker via `vite-plugin-pwa` (or equivalent): precache the full app INCLUDING the engine payload (`public/engine/*` — note gnubg.data is ~2MB, above workbox's default 2MB per-file cap; raise it), auto-update registration (new deploy → phone picks it up on next launch without user action), and a sane offline fallback. The app must fully work offline after first load: play, analyze, puzzles.
- Dev ergonomics: the service worker must not poison local development (`npm run dev` unaffected; preview/e2e still work — the existing Playwright suites must stay green; if the SW interferes with audit determinism, scope it out of the test environment deliberately and document).
- Installability verified: Lighthouse-style checks or Playwright assertions that the manifest and SW register on the preview build.
- Do NOT deploy — the coordinator handles Cloudflare deployment and device install after merge.

**Blocked by:** None (ticket 22 is worked inline in the main session on non-overlapping surfaces: `android/`, machine toolchain).

## Comments

**Implementation (agent, ticket branch `ticket/23-pwa-mobile-poc`).** `vite-plugin-pwa` 2.0.0 (supports vite 8), generateSW mode. Choices:

- **Manifest**: name `pg-backgammon`, short_name `Backgammon`, `display: standalone`, `start_url: /`. `theme_color` and `background_color` are both `#15130f` — the dark shell's `--bg` and the brand mark's ground; the installed app's status bar and splash stay dark in both app themes (the manifest supports only one color). The browser-tab tint still follows the OS: `index.html` carries paired `<meta name="theme-color">` tags with light/dark `prefers-color-scheme` media (`#fcfcfa` / `#15130f`). Note the in-app theme toggle can diverge from the OS scheme; the meta pair follows the OS, which is the closest the platform offers without scripting the meta.
- **Icons**: `public/icon-192.png`, `icon-512.png` (transparent rounded corners, straight from `favicon.svg`), `icon-maskable-512.png` (full-bleed `#15130f`, mark scaled to 72% for the maskable safe zone). Generated by `npm run icons` → `scripts/generateIcons.mjs`, which rasterizes the SVG with Playwright's bundled Chromium — no new image dependency. Regenerate whenever `favicon.svg` changes.
- **What's cached**: the SW precaches the entire app on install — all build assets plus everything matching `**/*.{js,css,html,svg,png,wasm,data}` in dist, which pulls in `engine/gnubg.{js,wasm,data}`. 13 entries, 4049.92 KiB total. `maximumFileSizeToCacheInBytes` raised to 4 MiB (gnubg.data at ~1.94 MiB brushes workbox's 2 MiB default per-file cap). `engine/PROVENANCE.md` is deliberately not cached. `navigateFallback: index.html` serves the SPA routes (`/analyze`, `/puzzles`, …) offline.
- **SW scope & registration**: root scope, registered from `src/main.tsx` via `src/pwa.ts` → `virtual:pwa-register` with `immediate: true`. In dev the virtual module is the plugin's no-op stub and `devOptions` stays off, so `npm run dev` never registers a worker (verified: dev server serves no manifest link and the no-op stub).
- **Update flow** (`registerType: 'autoUpdate'`): every launch/navigation revalidates `sw.js`; a new deploy installs in the background, skips waiting, claims clients, and the registration reloads the page once the new worker activates (`activated` + `isUpdate`) — so the phone picks up a deploy on next launch with no user action. No update prompt UI by design.
- **Test determinism**: SW registration stays ON in the Playwright suites — no scoping-out was needed. The autoUpdate client only reloads on `isUpdate`/`isExternal`, never on first install, and each Playwright test gets a fresh browser context, so no mid-test reloads and no cross-test cache bleed. Smoke and audit both ran green with the SW active.
- **Verification**: new `pwa` Playwright project (`npm run e2e:pwa`, `e2e/pwa.spec.ts`), run against the preview build like the other suites. Test 1 asserts the manifest is linked and served with the right fields and that all three icons are real PNGs (magic bytes checked). Test 2 boots its own `vite preview` on port 4399, waits for the SW to install/activate/claim, then **closes the server** (plus `context.setOffline(true)`) and reloads: the shell must boot SW-controlled, and a started match must reach the first actionable board control — which requires the full engine payload served from the precache. Closing the server (rather than only CDP offline emulation) guarantees even service-worker-initiated fetches genuinely cannot reach a network.
- **Automated vs human eyes**: everything above is automated. Still needs human eyes after deploy (coordinator): real install on the phone (A2HS prompt, icon rendering under the launcher mask, splash/status-bar color), a real offline session on-device, and an on-device update pickup after a second deploy.
- All gates run and green: `npm test` (783), `npm run lint`, `npm run build`, `npm run e2e` (2), `npm run e2e:audit` (1), `npm run e2e:pwa` (2).
